# Чернетка повідомлення викладачеві: advanced variant (відмінний рівень)

**Статус: НЕ надсилалось, відповіді немає.** Пункт «погоджений advanced variant» не виконано і не зараховується (див. `docs/security-review.md`, розділи 8.4 і 10). Нижче — чернетка, яку можна надіслати через канал курсу до реалізації.

Тема: ЛР 6, відмінний рівень, погодження advanced variant (Антоненко К. Ю., КБ-42).

Пропонується **спільний лічильник rate limit для двох екземплярів API на Redis** (замість in-memory fixed window; ризик R-02 у review).

- **Де працює Redis:** окремий локальний контейнер, порт лише на `127.0.0.1` (наприклад `127.0.0.1:56379`); зміна `infra/compose.yaml` — додаткова служба `redis` без паролів, cookie чи бізнес-даних.
- **Як API звертається:** .NET-клієнт `StackExchange.Redis`; лише для policy `search` (ключ `search:user:{userId}`), атомарний `INCR` + `EXPIRE` (TTL = вікно).
- **Що зберігається:** лічильник partition із TTL (без паролів, cookie, токенів і бізнес-даних).
- **Як покажу, що лічильник справді спільний:** два екземпляри API на портах 5080 і 5081; 3 запити alice до першого + 1 до другого → 429 на другому; bob на другому екземплярі → 200 (ізоляція partitions); після TTL — відновлення.
- **Failure mode:** при недоступному Redis — явна політика (fail-closed `503` для search або fallback на локальний лічильник); перевірка зупинкою контейнера; authentication/authorization не залежать від Redis.
- **Межі:** лише search limiter; без зберігання сеансів; без нових залежностей у production-коді поза клієнтом Redis.

Прошу підтвердити мету, межі й спосіб перевірки до реалізації. Якщо варіант не підходить — готова виконати рівноцінне нетривіальне security-розширення на ваш вибір.
