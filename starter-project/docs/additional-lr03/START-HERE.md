# Пакет WEB ЛР 1

Методичні рекомендації надано окремим PDF або DOCX. Почніть з таблиці «Порядок роботи»: інструменти → мости за самоперевіркою → запуск → дослідження → тренування → власне розширення → перевірки й подання.

Перед етапом 1 оберіть рівень виконання за таблицею «Що виконати на кожному рівні» на початку практичної частини. Звіт заповнюйте в копії шаблону поза starter-project (`lr01-report/report.md`), як описано в розділі 6.

Початковий застосунок — starter-project/. Команди застосунку виконують з цього каталогу, де є global.json. Архів не містить історії Git. Якщо надано адресу погодженого приватного репозиторію, клонуйте його за етапом 1, кроком 1.2 А методички. Якщо отримано лише ZIP, створіть локальний репозиторій у starter-project/ командами кроку 1.2 Б: git init -b main, перший commit baseline, гілка lab/1-system. Для початку університетський Git-сервер не потрібен.

Незалежні приклади мостів — one-time-examples/; до застосунку й його Git їх не додають. Відкрийте термінал у корені розпакованого ZIP, а потім cd one-time-examples/bridge-csharp-minimal-api або cd one-time-examples/bridge-browser-fetch-dom; далі README прикладу. Якщо перебуваєте в starter-project із ZIP, спершу перейдіть на рівень вище командою cd .. (дві крапки). Для клонованого starter відкрийте окремий термінал у ZIP.

Готові консольні приклади, EF TranslationProbe, фрагменти /latest, Bash/PowerShell команди та SQL — resources/copyable/. Прочитайте його README. Вони дублюють навчальні приклади методички, не є розв'язанням severity-summary і не додаються до вашого starter. Методичні ресурси поруч із PDF мають ті самі готові файли.

Усі працюють зі спільним baseline 2-A «Трекер інцидентів»; індивідуальних номерів немає. Тег v0.1.0 створюють після виконання ЛР 1 на перевіреному злитому commit. У Moodle подають звіт із доказами; DEL-01 передають через погоджений приватний remote або Git bundle за розділом подання. Декларація ШІ — розділ 7 звіту (копії шаблону `docs/report-template.md`); окремий журнал не потрібен.
